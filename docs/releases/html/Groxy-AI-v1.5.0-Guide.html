What Groxy AI v1.5.0 Delivers in Plain English: Groxy AI v1.5.0 introduces an intelligent database and store schema design layer. Merchants and operators get an eight-step guided interview that generates lean, zero-bloat .grab database migrations tailored to their exact catalog model (physical goods, digital downloads, product variants, inventory, subscription metadata, currency scale rules, operator taxes, bundles, facility fulfillment flags, and white-label partner references). For existing stores, an opt-in AI consultant inspects live table schemas and row counts (via statically configured commerce_inspect:read) alongside template query loops and 301 redirects, flags potential data loss before changes occur, writes verifiable canonical UTF-8 JSON Pre-Mutation Snapshots, and coordinates safe execution through single-winner atomic locking and explicit CLI maintenance.

1. Bespoke Store Architecture Quiz (POST /api/groxy/db/architect-quiz)

  • Eight Semantic Questions: Interactively configures store capabilities without manual SQL authoring. Generates clean ADR-024f migrations with exact ADR-025c base-10 decimal wire strings.
  • Grounding & Impact Diffs: When bound to an authorized target (such as commerce / commerce_inspect or a verified loopback Desk/Gashboard executor), inspects live sqlite_master tables, columns, indexes, and row counts to produce Before/After schema diffs and mint target-bound dtok_<hex> approval tokens.
  • Analytical-Only Safe Mode: Unconfigured or unregistered targets remain strictly analytical (503 response, zero approval tokens, zero mutations).

2. Opt-In “Talk to Groxy” Database Consultant (POST /api/groxy/db/consult)

  • Protected Site Setting (groxy_db_consultant_enabled): Default-disabled (403); must be explicitly enabled by authorized operators. Disabling the consultant immediately revokes outstanding consultant-minted plans at apply time.
  • Live Grounding & Impact Analysis: Queries row counts and live structure from commerce_inspect while checking SCHEMA-CONTEXT.md and SITE-CONTEXT.md for template ForEach query loops or slug_history 301 redirect dependencies.
  • Three-Tier Risk Classification: Categorizes proposed schema changes into Safe (additive columns/tables), Caution (empty tables or operational adjustments), and High-Risk Data Loss (dropping tables/columns with existing rows or active template dependencies). High-risk proposals require explicit risk_acknowledged: true to proceed.

3. Target Locks, Logical Snapshots & Compliant Apply (/apply & /reconcile)

  • Atomic Single-Winner Coordination: Durable SQLite locking via db_target_locks and single-use approval claiming via db_consultant_ledger ensure that concurrent worker races produce exactly one 201 winner and 409 conflict/replay rejection.
  • Pre-Mutation Logical JSON Snapshots: Queries commerce_inspect and deterministically captures storage/snapshots/snap_db_<id>.json with canonical sorted keys and SHA-256 verification before any mutation receipt is issued. Snapshot restore logic preserves subsequent non-affected orders.
  • Strict Separation of HTTP Handlers & DDL: HTTP handlers never execute DDL. The apply endpoint generates canonical CLI maintenance scripts (storage/approved_migrations/mig_<plan_id>.grab) with a .receipt.json sidecar and status maintenance_ready, or dispatches to a verified loopback executor (127.0.0.1:9490). Post-maintenance reconciliation (POST /api/groxy/db/reconcile) reads back live schema state, verifies table creation, transitions the receipt to applied, and safely releases the target lock.
