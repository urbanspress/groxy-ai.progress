1. Design four grounded messages

POST /api/groxy/email-flows/design reads the saved Brand DNA and Site Context, fetches the live Builder design tokens, and stages an ordered four-message preview: Order Receipt & Welcome, Quick-Start / Setup Guide, Check-In & Review Request, and Targeted Cross-Sell / Reorder. Missing customer and sender facts remain explicit placeholders. Exact monetary strings stay strings, including trailing zeroes.

Every message includes a plain-text body and semantic layout with unsubscribe and physical-address placeholders. The flow is draft-only; timing suggestions do not schedule delivery.

2. Review and save one CMS draft

The dashboard shows the preview and requires a separate Approve & Save Draft Flow action. The one-use etok_* approval token is bound to the staged flow ID, step count, digest, CMS destination, and operator. Invalid target attempts return 403; replay returns 409. The flow is saved as one new GrabLab CMS draft through create_entry_draft. Groxy does not send or activate email.

CAN-SPAM/GDPR-oriented unsubscribe and sender-address placeholders are visible in every message. Consent, suppression, sender identity, and unresolved merge fields remain activation blockers for a future delivery system.

3. Routes

  • POST /api/groxy/email-flows/design validates inputs, grounds a four-step preview, and stages the draft.
  • POST /api/groxy/email-flows/apply checks CSRF and target binding, then creates one draft entry only.

4. Verification and compatibility

Frozen upstream repositories were not modified. Release promotion is pending the remaining canonical digest and atomic single-winner review.
